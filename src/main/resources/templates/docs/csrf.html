クロスサイトリクエストフォージェリ (CSRF)

何が起きるのか

被害者がログイン中のサイトに対して、攻撃者の用意したページから「意図しないリクエスト」を発射させる攻撃。 ログイン中の Cookie はブラウザが自動送信するため、被害者が気づかない間に投稿削除や設定変更が走ります。

再現手順（VULNERABLE 版）

  1. VULNERABLE 版にログインし、適当な投稿を作成する
  2. 下記のような HTML を別タブ（同一オリジンでなくて良い）で開かせるだけで削除が走る: 
    <img src="http://localhost:8080/vulnerable/posts/1/delete">
  3. 編集も同様に ...?title=hacked&content=hacked を img や iframe から呼べる

VULNERABLE 側のコード

// VulnerablePostController
@GetMapping("/{id}/delete")
public String delete(@PathVariable Long id) { ... }

@GetMapping("/{id}/update")
public String updateViaGet(@PathVariable Long id,
                           @RequestParam String title,
                           @RequestParam String content) { ... }

さらに VulnerableSecurityConfig 相当のフィルタチェーンで CSRF を disable() しています。

SECURE 側のコード

// SecurityConfig#secureFilterChain
.csrf(Customizer.withDefaults())
// SecurePostController
@PostMapping("/{id}/update")
public String update(...) { ... }
@PostMapping("/{id}/delete")
public String delete(...) { ... }

対策のポイント

  • 状態を変えるリクエストは GET ではなく POST/PUT/DELETE にする
  • CSRF トークン（Spring Security が自動で隠しフィールドに埋め込む）を必ず検証する
  • SameSite=Lax Cookie も併用すると効果的
